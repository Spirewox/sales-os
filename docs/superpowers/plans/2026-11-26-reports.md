# Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Analytics gets a Reports tab. It holds a library of ready-made tabular reports for the selected period and location, which can be read on screen, exported to CSV and printed. It also holds the person's own saved Explore reports.

**Architecture:**
- **The library:** a registry in `lib/reports.ts` defines each ready-made report: key, title, description, group, permission and whether it uses the period.
- **The data:** one endpoint per report, `GET analytics/reports/:key`, returns columns, rows and totals in one shape. A single viewer renders any report, and the mock computes each from sample data.
- **Saved reports:** they store an Explore query (dataset, measure, group by, filters, chart) through `analytics/reports/saved`, and the viewer re-runs it with `insights/explore/query`.
- **Shared plumbing:** CSV comes from Plan 1's `buildCsv`. Print uses the browser with a print stylesheet. The period and location come from the Analytics page's existing `useInsightScope`, so reports follow Plan 4's location scope too.

**Tech Stack:** Next.js 16.2.3, React 19, TanStack Query, `node --test`, the `@/components/app` kit (`SectionTabs`, `DataTable`, `KpiStrip`, `EmptyState`, `Skeleton`, `OverflowMenu`, `SectionErrorBoundary`).

**Spec:** The user's request "reports module for analytics" plus [the shared notes](2026-11-26-README.md). Depends on Plan 1 (`lib/export.ts`).

## API contract (backend)

| Call | Shape and behaviour |
|------|---------------------|
| `GET analytics/reports/:key?period=&date_from=&date_to=&hub_id=` | Returns `{ data: ReportResult }`. Unknown key: 404. Missing permission: 403. Rows are capped at 10,000, and the cap is reported. |
| `ReportResult` | `{ columns: { key: string; label: string; kind: 'text' \| 'money' \| 'number' \| 'percent' \| 'date' }[]; rows: Record<string, string \| number \| null>[]; totals: Record<string, number>; capped: boolean; generatedAt: string }` |
| `GET analytics/reports/saved` | Returns `{ data: SavedReport[] }` for the signed-in user only. |
| `POST analytics/reports/saved` | Body `{ name, dataset, measure, groupBy, filters, chart }`. Returns `{ data: SavedReport }`. The name is 1 to 60 characters and unique per user (409 `You already have a report with that name.`). |
| `DELETE analytics/reports/saved/:id` | Allowed for the owner only. |

## Global Constraints

- **Tab:** `{ id: 'reports', label: 'Reports' }`, placed after `explore` in the `tabDefs` of `app/(app)/analytics/page.tsx`, and typed into `AnalyticsTab`.
- **Opening a report:** the report sits in the URL as `report=<key>` or `report=saved:<id>`. With no report, the tab shows the library.
- **Library layout:**
  - Groups follow the table order (Sales, Customers, Credit, Inventory, Suppliers, then `Saved reports`), using `<h3>` in the Analytics `sectionTitle` style.
  - Each report is a `rounded-xl` card button with its title and description. A report the user lacks permission for is hidden, not disabled.
- **Viewer layout:**
  - A `Back to reports` ghost button.
  - The report title, plus a muted `text-xs` line: `<period range> · <location label>`, or `As of <date>` for no-period reports. Use the page's existing `activeRange` and `hubScope` label.
  - A `KpiStrip` of the money and number totals, at most 4, in column order.
  - A `DataTable` with money in `formatMoney`, right-aligned, and percent at 1 decimal.
  - Actions: `Export CSV` (primary outline button) and `⋯`, which holds `Print`. Saved reports also get `Delete report` (destructive, last, confirmed with `Delete <name>?` and `Delete`).
- **No-period reports** (`credit-aging`, `stock-valuation`): the page's `PeriodSelect` stays visible but has no effect. Show a muted `text-xs` note: `This report shows today's position, so the period does not change it.`
- **Saving from Explore:**
  - Explore Build gets a `Save as report` outline button. It opens a `ModalDialog` with a `Name` field (required, 60 maximum) and `Save`.
  - Toast: `Saved. Find it in Reports.`
- **Printing:**
  - `@media print` in `app/globals.css` hides the sidebar, top bar, Analytics header controls, tabs and the viewer's action buttons.
  - The viewer prints at full width, with the table un-paged: every row prints, even when the on-screen table is paged.
- **The CSV file:** `exportFilename(\`report-${key}\`)`, from Plan 1. The first rows are `Report,<title>`, `Period,<range>`, `Location,<label>` and an empty line, then the table, then a `Total` row when there are totals.
- **States:**
  - Loading: `Skeleton` rows at the table's height.
  - No rows: `EmptyState` (compact) titled `Nothing in this period` with the description `Try a longer period or another location.`
  - Error: a `SectionErrorBoundary` around the viewer.
  - Capped: a `text-xs` warning above the table: `Showing the first 10,000 rows. Narrow the period or location to see the rest.`

## Review Focus

1. **Changing period or location with a report open:** the report refetches with the new scope and the URL keeps `report=`. The query key includes `scope`, and Task 3 asserts that `reportQueryKey` changes with it.
2. **A shared link to a report the user can't open:** for example, a Finance user given `stock-valuation` without `inventory.view`. They see the library with a toast, `You don't have access to that report.`, and `report` is cleared. Tested in `resolveReportParam`.
3. **A saved report whose Explore fields no longer exist:** the dataset or measure has since been removed from `lib/explore.ts` `DATASETS`. The viewer shows `EmptyState` titled `This report can't run any more` with the description `Its data source changed. Delete it and save it again from Explore.` Tested in `savedReportRunnable`.
4. **Totals that shouldn't be added up:** Avg order and Share % are never summed into totals or the KPI strip. `summableColumns` picks only `money` and `number` columns that the server returned in `totals`, and is tested.
5. **Printing a long report:** every row prints, not just the current page. The viewer renders a print-only plain `<table>` of all rows (`hidden print:table`) next to the paged `DataTable` (`print:hidden`). Checked in the browser's print preview in Task 4.

### Task 1: The report registry and result helpers

**Files:**
- Create: `lib/reports.ts`

**Interfaces:**
- Consumes: Plan 1 `buildCsv`, `ExportColumn`, `csvDate`.
- Produces:
  - `type ReportKind = 'text' | 'money' | 'number' | 'percent' | 'date'`
  - `type ReportColumn = { key: string; label: string; kind: ReportKind }`
  - `type ReportResult = { columns: ReportColumn[]; rows: Record<string, string | number | null>[]; totals: Record<string, number>; capped: boolean; generatedAt: string }`
  - `type ReportDef = { key: string; group: 'Sales' | 'Customers' | 'Credit' | 'Inventory' | 'Suppliers'; title: string; description: string; permission: Permission; usesPeriod: boolean }`

  - `visibleReports(can: (p: Permission) => boolean): ReportDef[]`
  - `resolveReportParam(param: string | null, can, saved: SavedReport[]): { kind: 'library' } | { kind: 'builtin'; def: ReportDef } | { kind: 'saved'; report: SavedReport } | { kind: 'denied' }`

  - `reportCsv(def: { title: string }, meta: { range: string; location: string }, result: ReportResult): string`
  - `savedReportRunnable(r: SavedReport): boolean`: checks `DATASETS` (`lib/explore.ts`) for the dataset, measure and groupBy.
  - `reportQueryKey(key: string, scope: InsightScopeParams): unknown[]`: `['analytics-report', key, scope]`.
