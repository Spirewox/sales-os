# Sales OS: five features, five plans

These five features are separate subsystems, so each has its own plan. Each plan ships working, testable software by itself. Run them in this order. A later plan uses what an earlier one makes, and the dependencies are listed below.

| # | Plan | Builds | Uses |
|---|------|--------|------|
| 1 | [Data export](2026-11-26-data-export.md) | `lib/export.ts`, `hooks/use-export.ts`, CSV export on every list that lacks one | |
| 2 | [Inventory archiving](2026-11-26-inventory-archiving.md) | Archive and restore a product, an Archived view, pickers that leave archived products out | Plan 1 (the stock export gains a status column) |
| 3 | [Business profiles with contacts](2026-11-26-business-contacts.md) | Several contacts per business customer, each with WhatsApp | |
| 4 | [Multi-location managers](2026-11-26-multi-location-managers.md) | Users who manage several locations, an "All my locations" scope | |
| 5 | [Reports](2026-11-26-reports.md) | A Reports tab in Analytics: ready-made reports, saved Explore reports, CSV and print | Plan 1 (CSV), Plan 4 (the location scope reports respect) |

## What all five share

- **The backend is not in this repo.** The Nest API lives elsewhere, behind `NEXT_PUBLIC_API_URL`. Each plan starts with an **API contract** section: the endpoints and fields the backend team must add. The frontend tasks build against that contract and answer it from `lib/mock-api/handler.ts`, so every feature works and can be checked in local mock mode (`npm run dev`, no `NEXT_PUBLIC_API_URL`, any email and password).
- **Tests.** `npm test` runs `node --test` over `lib/**/*.test.ts`. That is why each plan puts its rules in pure `lib/` modules with tests, and keeps the screens thin. Screens are checked in the browser pane and with `node scripts/check.mjs`.
- **UI rules** (from `AGENTS.md`, apply to every task):
  - Read `public/llms.txt`, `public/system/rules.md` and the component twins in `public/system/` before UI work.
  - Use `@/components/app` and `@/components/ui`, and the tokens in `app/globals.css`.
  - Copy is in sentence case with no em-dashes. Customers are contacted by WhatsApp only, so no Call buttons.
  - Never remove a KPI, chart, section, column or field.
  - Before finishing, run `node scripts/check.mjs` and look at each changed screen at 390 and 1280 px in light and dark.
- **Next.js 16.2.3.** Read the relevant guide in `node_modules/next/dist/docs/` before touching routing or data code.

## Decisions taken in these plans that a person may want to change

1. **Who can export.** New exports use the module's own view permission, as Customers and Sales exports do today. A separate "Export data" permission would need a new backend key. Plan 1, Task 2 notes where to add it.
2. **Archiving with stock asks first (changed 26 Nov).** A product with stock on hand can be archived after a confirm that spells out what happens to the stock; open stock requests still block it. Plan 2's `archiveBlocker` and `archiveStockWarning` hold that rule.
3. **The primary contact of a business is the customer's name and phone.** List columns, search and the existing API fields keep working unchanged (Plan 3).
4. **Cashiers stay on one location.** Their till PIN is tied to that location (Plan 4).
5. **Saved reports are private to the person who saved them.** Sharing and emailed schedules are left for later (Plan 5).
